# Category Intelligence — offline adapter + shadow evaluation

This directory is the offline evaluation harness that answered: *does the
phrase-level "category brain" improve routing, and is it safe to integrate?*
Verdict: **SAFE_TO_INTEGRATE_WITH_LIMITS** — review + confidence signal only,
never selection.

That limited integration is now LIVE in shadow form:
`src/lib/routing/category-intelligence.ts` (TS port of the adapter's shipped
config) is called from `src/lib/routing/shadow.ts` behind
`ROUTING_SHADOW_ENABLED` and writes `ciShouldReview` / `ciConfidence` /
`ciSignal` onto `routing_decision_logs`. It is observational only — it never
affects selection, provider notifications, lead visibility, or payments.
Parity between the TS port and the Python adapter is pinned by
`pnpm routing:ci-signal` (66-case fixture generated by
`build_ci_parity_fixture.py`).

The phrase brain itself (`phrase_category_stats.json`,
`category_phrase_summary.json`) is produced in the separate
`~/Documents/KATEGORIJOS + 200K-uzklausu` data-science project by
`analyze_category_phrases.py`. The large inputs are copied (gitignored) under
`data/routing/`; regenerate them there, not here.

## Files

| file | what |
|---|---|
| `category_intelligence_adapter.py` | Loads the brain, normalizes a request the same way the analysis did, extracts 2–5 word phrases, returns a structured signal: `matched_phrases`, `category_boosts` (full), `ranking_boosts` (safe subset), `ambiguity_signals`, `redirect_hints`, `should_trigger_review`, `explanation`. Scoring config is the `SCORING` block at the top. |
| `multi_routing_baseline.py` | Verbatim copy of the production router (`multi_routing_classifier.py`); only the taxonomy path is repointed. Used as the baseline. |
| `evaluate_category_intelligence_shadow.py` | Runs baseline vs baseline+intelligence over `golden_eval_300`, an ambiguous-heavy slice, and a random unlabeled sample. Writes the 6 outputs under `data/routing/category-intelligence/evaluation/`. Config is the `EVAL` block. |
| `test_category_intelligence_adapter.py` | Minimal validation (`python3 test_category_intelligence_adapter.py`). |
| `build_phrase_brain_compact.py` | Compacts the 24MB stats JSON into the committed ~1MB `src/lib/routing/data/phrase-brain.v1.json` the TS shadow signal imports. Re-run after regenerating the brain. |
| `build_ci_parity_fixture.py` | Regenerates `src/lib/routing/__tests__/fixtures/ci-parity.json` (TS↔Python parity cases) from the Python adapter. |

## Run

```bash
python3 scripts/ai-routing/test_category_intelligence_adapter.py
python3 scripts/ai-routing/evaluate_category_intelligence_shadow.py
```

## Design contract (do not weaken without re-running the eval)

- Phrases are a **scoring / ambiguity signal, never a hard rule.** They never
  select a category on their own and never override the router.
- The shipped configuration leaves **selection on the router** and uses the
  signal only to (a) raise confidence when a strong/medium phrase agrees, and
  (b) cap confidence + flag manual review on ambiguity / redirect / conflict.
- Re-ranking the router by phrase boosts is measured but **rejected** — it is
  net-negative on gold (high-volume umbrella categories out-boost the correct
  specific trade). See the report's "rerank experiment" section.

See `data/routing/category-intelligence/evaluation/category_intelligence_eval_report.md`
for the latest result and recommendation.
